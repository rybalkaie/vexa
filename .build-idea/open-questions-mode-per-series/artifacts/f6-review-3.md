## КРИТ-1. Пред-фильтр вернул конечный словарь: 13 из 30 живых просьб → тишина

```
Класс:              КРИТ
Цитата:             scripts/notary/lib/send_artifact.py:330 —
                        if not looks_like_request(t):
                            return False
                    (+ словарь маркеров `_REQUEST_EXTRA`, send_artifact.py:156-176)
```

Критерий 1 фазы: «ИИ определяет намерение, код верифицирует и исполняет».
Фактически ИИ определяет намерение **только среди фраз, которые словарь уже признал
просьбой**. Словарь стал длиннее (≈30 основ вместо ≈10), но остался конечным — то
есть ровно то, про что жалоба ISS-51: «конечный словарь проигрывает живой речи всегда».

**Как воспроизвести** (из корня worktree):

```sh
cd scripts && python3 -c "
import sys; sys.path.insert(0,'.')
from notary.lib import send_artifact as sa
ai = lambda t, s: {'intent':'send','artifact':'unknown','why':''}
for t in ['А можно протокол?','Прошу протокол вчерашней встречи',
          'Мне бы протокол последней встречи','Список открытых вопросов в студию',
          'Можешь ещё раз открытые вопросы?','Бот, протокол']:
    print('зовём модель=%-5s итог=%-6s | %s' % (
        sa.should_ask_ai(t, allow_bare_file=False),
        sa.detect_artifact_request(t, allow_bare_file=False, answer_fn=ai), t))
"
```

→ все шесть: `зовём модель=False итог=None`. Модель не спрашивают, бот молчит.

Полная выборка (30 реалистичных просьб в чате серии, без реплая, флаг ON, модель
отвечает «send»): **понято 17, молчит 13**. Разбивка причин молчания:

| фраза | почему молчит |
|---|---|
| А можно протокол? | пред-фильтр: нет маркера просьбы |
| Протокол будет? | пред-фильтр |
| Открытые вопросы по нашей встрече есть где-то? | пред-фильтр |
| Мне бы протокол последней встречи | пред-фильтр |
| Ещё разок открытые вопросы, пожалуйста | пред-фильтр («разок» ≠ «раз + глагол») |
| Можешь ещё раз открытые вопросы? | пред-фильтр (после «можешь» нужен глагол из списка) |
| Пожалуйста, актуальный список открытых вопросов | пред-фильтр |
| Список открытых вопросов в студию | пред-фильтр |
| Бот, протокол | пред-фильтр |
| @notary_bot протокол встречи | пред-фильтр |
| Прошу протокол вчерашней встречи | пред-фильтр («прошу» в словарь не попало) |
| Верни, пожалуйста, дайджест по встрече | ГЕЙТ: `detect_status_intent` = `reopen` |
| Жду протокол по встрече | ГЕЙТ: `detect_status_intent` = `wait` |

Последние две — отдельный подслучай: «верни» и «жду» стоят рядом с **названием нашего
документа**, но гейт статус-разговора смотрит только на статус-маркер и уступает
роутам ниже; без реплая роутов ниже нет → тишина.

```
Предлагаемая правка: развести два вопроса, которые сейчас слиты в один.
  • Объект назван ОДНОЗНАЧНО («протокол», «открытые вопросы», «дайджест», «висяки»)
    → зовём модель ВСЕГДА, без маркера просьбы. Проверено: у всех 11 фраз, убитых
    пред-фильтром, `_object_classes` даёт prot или dig_strong = True (11 из 11),
    то есть это правило возвращает все 11 и ничего не ломает.
  • Объект СЛАБЫЙ («вопрос…», «задач…», «что осталось», «файл/версия/документ»)
    → маркер просьбы обязателен, как сейчас (это и была защита ревью-1 🔴-1:
    «у нас вопрос» дайджестом не становится).
  • В гейте статус-разговора: если в той же фразе назван наш документ ОДНОЗНАЧНО
    и реплая нет — не уступать (уступать некому), уступать только по реплаю.
```

## ВАЖНО-2. При слабом объекте перехват держит НЕ код, а суждение haiku

```
Класс:              ВАЖНО
Цитата:             scripts/notary/lib/send_artifact.py:310 —
                        return dig_strong or (dig_weak and looks_like_request(t))
```

`_digest_named` объявляет дайджест «названным», если в тексте есть голая основа
«вопрос…/задач…/что осталось» **и любой** из ≈30 маркеров просьбы. Маркеры —
частотные слова рабочего чата: `покаж`, `глян`, `напомн`, `нуж(ен|на|ны)`,
`потеря(л|ли)`, `отправ`, `подел(ись|итесь)`. В результате между «глянь задачи в
битриксе» и вывалившимся в чат дайджестом стоит только ответ модели.

Тест `_greedy` («жадная модель») в наборе фазы заявляет обратное: *«Так проверяется,
что перехват держит КОД, а не вежливость промпта»* (test_iss51_send_artifact_ai.py:113).
Для слабых объектов это неверно — `TestBareQuestionWords` берёт только фразы **без**
маркера просьбы, то есть проверяет ветку, где защита действительно кодовая.

**Как воспроизвести:**

```sh
cd scripts && python3 -c "
import sys; sys.path.insert(0,'.')
from notary.lib import send_artifact as sa
ai = lambda t, s: {'intent':'send','artifact':'unknown','why':''}
for t in ['глянь задачи в битриксе','напомни Игорю про задачи',
          'покажите вопросы аудитории на конференции',
          'потеряли задачу по складу, надо переоформить']:
    print(sa.detect_artifact_request(t, allow_bare_file=False, answer_fn=ai), '|', t)
"
```

→ все четыре: `digest`.

На выборке из 20 бытовых фраз (не пересекается с `CHATTER` из тестов) при «жадной»
модели **14 уезжают документом в чат**, из них 12 — дайджестом по слабой основе.
Модель разбора — `claude-haiku-4-5-20251001` (`mixed_reply_split._SPLIT_MODEL:77`),
самая дешёвая в линейке; ставить на её суждение единственную защиту от «бот вывалил
внутренний список задач в чат с клиентом» — дорогая ставка.

```
Предлагаемая правка: слабую основу считать названием дайджеста только при
                     однозначном контексте — reply_surface == "digest" ЛИБО рядом
                     слово про встречу/дайджест («задачи по встрече», «что осталось
                     с планёрки»). Тогда исход «глянь задачи в битриксе» предрешён
                     кодом при ЛЮБОМ ответе модели, а «дай посмотреть вопросы»
                     (фраза из критерия 4) продолжает работать: там есть «встреча»
                     в контексте либо однозначная формулировка.
```

## ВАЖНО-4. Потолок отпускает поток, но процесс модели не убивает

```
Класс:              ВАЖНО
Цитата:             scripts/notary/lib/send_artifact.py:498-503 —
                        th.join(_hard_cap())
                        if th.is_alive():
                            logger.warning("[send-artifact-ai] потолок ожидания %.0fs исчерпан …")
                            return None
```

Главный поток действительно отпускается (это проверено). Но subprocess `claude`
никем не убивается: он живёт до СВОЕГО таймаута, а тот поднят полом
`CLAUDE_MIN_TIMEOUT` — на проде под длинные встречи он и стоит (комментарий кода
называет замер 900 с). То есть каждая упёршаяся просьба оставляет висеть процесс
модели до 15 минут; десять просьб подряд — десять процессов.

**Как воспроизвести:**

```sh
mkdir -p /tmp/slowbin && printf '#!/bin/sh\nsleep 60\necho "{}"\n' > /tmp/slowbin/claude
chmod +x /tmp/slowbin/claude
cd scripts && PATH=/tmp/slowbin:$PATH ENABLE_SEND_ARTIFACT_AI=1 CLAUDE_MIN_TIMEOUT=900 python3 -c "
import sys, time; sys.path.insert(0,'.')
from notary.lib import send_artifact as sa
sa._AI_TIMEOUT_CAP = 2
t=time.monotonic(); print(sa.detect_artifact_request('Вышли актуальный файл с открытыми вопросами', allow_bare_file=False)); print('ждали %.1f c' % (time.monotonic()-t))
"
ps -eo pid,etime,command | grep '[s]leep 60'      # процесс жив после выхода python
```

→ `None`, «ждали 2.1 c» — потолок работает; `ps` показывает живой `sleep 60` уже после
завершения питона.

Побочная арифметика на константах кода (не воспроизводил, но считается по коду):
`_AI_TIMEOUT_CAP = 30` × 6 просьб в одном батче `getUpdates` = 180 с без heartbeat,
а watchdog рестартует листенер при разрыве > 3 мин (docstring `meetings_listener.py:17-18`);
`save_offset` вызывается ПОСЛЕ всего батча (`meetings_listener.py:3887`) — значит
Telegram отдаст тот же батч заново, и цикл повторится.

```
Предлагаемая правка: вести вызов через subprocess.Popen и по истечении потолка
                     делать kill() (или добавить в `claude_cli` явный аргумент
                     «не поднимать таймаут полом CLAUDE_MIN_TIMEOUT» и пользоваться
                     им здесь). Потолок 30 с при синхронном вызове в цикле
                     стоит опустить до 8-10 с — разбор одной фразы на haiku
                     занимает секунды, а цена ожидания платится всем чатом.
```

## ВАЖНО-5. Критерий 2 исполнен частично: гейт статусов перестал быть безусловным

## ЖЕЛАТЕЛЬНО-8. `understand_request` нарушает свой докстринг

## ЖЕЛАТЕЛЬНО-9. `да[йте]+\b` быстрого пути ловит «по дате»

```
Класс:              ЖЕЛАТЕЛЬНО
Цитата:             scripts/notary/lib/send_artifact.py:95 —
                        r"да[йте]+\b|покаж|повтор|…"
```

`да[йте]+` матчит слово «дате». Любая фраза «… по дате протокола …» проходит как
«глагол отправки + объект» и отдаёт протокол **быстрым путём, без модели** — то есть
ни промпт, ни верификация тут не спасают.

**Как воспроизвести:**

```sh
cd scripts && python3 -c "
import sys; sys.path.insert(0,'.')
from notary.lib import send_artifact as sa
for t in ['уточню по дате протокола','сверимся по дате протокола']:
    print(sa.detect_artifact_request(t, allow_bare_file=False), '|', t)
"
```
→ обе: `protocol`.

```
Предлагаемая правка: заменить на `\bда(?:й|йте)\b` (регрессии нет: «дай/дайте» —
                     единственные формы, ради которых ветка заводилась).
```

# Чего проверить не смог и почему

- **Настоящее качество модели на пред-фильтрованных фразах.** Наружу не ходил
  (запрещено правилами прогона), поэтому «жадная модель» — верхняя оценка утечки
  (14 из 20), а не прогноз. Нижняя оценка неизвестна: чтобы её получить, нужен прогон
  тех же 20 фраз через реальный haiku с боевым промптом. **Это стоит сделать перед
  включением флага на проде** — цена ошибки в эту сторону (внутренний список задач в
  чате с клиентом) выше, чем в другую.
- **Поведение под нагрузкой в боевом листенере** (батч из нескольких просьб, watchdog,
  повторная доставка батча после рестарта). Считал по константам кода; поднимать
  боевой листенер и телеграм-трафик в песочнице не стал.
- **Реальная отправка PDF/дайджеста** (`_resend_protocol` / `_resend_digest`) —
  везде подменял, чтобы ничего не ушло наружу. Проверял только их ветвление по кодам
  результата, не сам рендер и доставку.
- **Что именно вернёт `resolve_chat_id`, если серию развели командой «шли сюда»** —
  тут нужен боевой реестр; ограничился чтением кода (в источнике просьбы бот
  не молчит — пишет «Прислал открытые вопросы в чат этой серии»).
- **Кто имеет право просить.** Allowlist авторов (FB8) есть у шлюза правок, у
  артефакт-роута его нет: файл получит любой участник группы, повторно и без
  ограничения частоты. Не разбирал — это ось безопасности, не моя; отмечаю, чтобы
  не выпало между ревьюерами.
