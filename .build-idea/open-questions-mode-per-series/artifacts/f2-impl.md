## По каждому из шести пунктов плана

### 1. Узкий детерминированный триггер (обе стороны + явное имя серии) ✅

`lib/mode_command.py`, `parse_mode_command(text) -> ModeCommand | None`.
ИИ не зовётся вообще — регулярки, как и требует план.

Что понимается:

| Сказано | Понято |
|---|---|
| «эта серия — накопление» / «эта серия накопление» | `set carry`, серия из контекста |
| «эта серия — шпаргалка» / «эту серию — в шпаргалку» | `set last-only` |
| «серию Координация — шпаргалка» | `set last-only` для названной серии |
| «серию anzhee-direktorat — накопление» | то же по slug (внутренний дефис не ломается) |
| «переключи серию координация в режим шпаргалки» | `set last-only` |
| «копи вопросы» | `set carry` |
| «не копи» / «не копи вопросы» / «перестань копить вопросы» | `set last-only` |
| «только с прошлой встречи» / «вопросы только с прошлой встречи» | `set last-only` |
| «в каком режиме эта серия?» / «какой режим у этой серии» | `query` |

**Три сита, которыми триггер держится узким** (иначе переписка в группах становится
переключателем режимов):

1. **Слово режима — последнее значимое в сообщении.** «Эта серия — шпаргалка» —
   команда; «у нас накопление вопросов по этой серии растёт» — рассказ, и слово
   режима стоит не на месте приказа. Хвостовой мусор («пожалуйста», «вопросов»)
   не мешает.
2. **Отрицание перед словом режима → отказ разбирать.** «Эта серия — шпаргалка, а
   не накопление» → `None`: спорную формулировку не разгадываем.
3. **Вопросительный знак → только форма-вопрос.** «Почему ты не копишь вопросы?» —
   вопрос человека, а не приказ перестать копить.

Плюс для формы-императива: глагол должен стоять в начале (первые 5 слов) и без
подлежащего перед ним — «мы копим вопросы уже месяц» не команда.

**Дата `YYYY-MM-DD` в тексте → `None`** (тот же приём, что у `_parse_set_chat`):
датированные сообщения принадлежат командам коррекции протокола. Без этого гейта
правка «поправь протокол koord 2026-05-28: серию переименовали, теперь это
шпаргалка» молча уехала бы в переключатель режима, а правка протокола потерялась.

Проверено, что НЕ перехватывается (тест-батарея из 15 фраз): «привет, как дела»,
«спасибо!», «закрой третью», «завтра встречаемся в 11», «мы копим вопросы уже
месяц», «у нас накопление вопросов по этой серии растёт», «данные только с прошлой
встречи», «не копи деньги, вложи в дело», «сделал шпаргалку по проекту», «нужна
копия протокола», «у нас в компании накопление долга», «вопросы копились с мая»,
«почему ты не копишь вопросы?», «эта серия — шпаргалка, а не накопление», «по этой
серии всё сделано». Отдельно: команда смены чата («серию koord шли сюда») —
не крадётся, остаётся своему роуту; проверено ещё и через `parse_correction_command`.

### 2. Owner-гейт ✅

Образец соблюдён (`maybe_route_to_set_chat_command`): в группе режим меняет только
владелец (`from.id == allowed_chat`; в личке `chat.id == user.id`). Не владелец →
`False` + строка в лог, **без отказ-сообщения** — сообщение уходит роутам ниже, как
и у соседа (обоснование — в блоке решений).

Сверх плана закрыл дыру, которую нашёл при перечитывании своего же дифа:
**вопрос о режиме** гейта не имеет (он ничего не меняет), но посторонний, написавший
боту в личку, мог спросить про ЧУЖУЮ серию по имени и получить и режим, и — через
«не нашёл серию» — список внутренних имён всех встреч владельца. Теперь: спрашивать
про серию **по имени** может только владелец; участник группы может спросить про
серию **своего** чата (режим виден ему и так, по формату встреч); список известных
серий печатается только владельцу.

> Серия «Директорат» сейчас в режиме накопления: незакрытые вопросы переносятся из
> встречи во встречу, утром прихожу с дайджестом и прошу статусы. Переключить:

## Что записано в реестр и почему во ВСЕ записи серии

`set_open_questions_mode_for_series(series, mode, watched) -> int` пишет режим
**всем** записям серии.

Причина не косметическая: читатель `series_open_questions_mode` (Ф1) берёт ПЕРВОЕ
валидное значение среди записей серии. Одна серия обычно = несколько записей
(несколько встреч/календарей; Ф5 дедупа ещё и дубли разгребает). Записав режим в
одну запись, мы получили бы read-after-write, зависящий от ПОРЯДКА записей в файле:
устаревшее значение выше молча перебило бы только что заданное — владелец увидел бы
«✅ принял», а поведение не изменилось. Тот же выбор сделан у соседа
`set_telegram_chat_id_for_series`. Мутация M7 («писать только в первую запись»)
красит тест.

## Что решил сам (и почему)

1. **Не-владельцу — молчание, а не отказ-сообщение.** План требует «отказ
   не-владельцу», и его можно было сделать видимым («режим меняет только
   владелец»). Выбрал поведение соседа `maybe_route_to_set_chat_command`: `False` +
   строка в лог. Два довода: (а) `False` отдаёт сообщение роутам ниже — оно может
   быть законным статус-ответом или правкой, а ответ его бы проглотил; (б) триггер
   узкий, но не идеальный, и бот, читающий нотацию участникам группы на случайно
   совпавшую фразу, хуже молчания. Переделка — три строки.
2. **Вопрос о режиме без owner-гейта** (но только про серию своего чата). Режим
   виден участникам и так — по формату встреч; запрет спрашивать про свою же серию
   выглядел бы дуростью. Спрашивать про ЧУЖУЮ серию по имени — только владельцу.
3. **Строка в чат серии НЕ дублируется**, когда команду дали прямо в чате серии:
   подтверждение уже там и говорит то же самое. Формально план просит «шлёт в чат
   серии одну строку» — считаю выполненным (людям сообщение приходит в обоих
   сценариях, просто в одном оно совмещено с подтверждением).
4. **Идемпотентный повтор ничего не пишет и не шумит в чат серии.** «Ещё раз
   шпаргалка» → «и так в режиме шпаргалки», реестр не трогается, участники не
   получают уведомления о смене формата, которой не было.
5. **Режим пишется во ВСЕ записи серии** — обоснование выше, отдельным блоком.
6. **Подтверждение накопления честно говорит про чистый лист** (решение владельца 7,
   РИСК6) — в плане пункта 3 этой фразы нет, добавил осознанно.
7. **Парсер вынесен в отдельный `lib/mode_command.py`**, а не дописан в
   `correction_command.py`: последний вне карты владения фазы, и класс команды
   другой (настройка серии без даты). Границы соблюдены, дублирования нет.
8. **Мутации проверены с `PYTHONDONTWRITEBYTECODE=1`** после того, как обнаружил
   враньё харнесса (см. выше).
