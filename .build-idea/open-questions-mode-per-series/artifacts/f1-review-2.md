## 🔴 Чинить в этой фазе

### Н1. Битый `watched.yaml` теперь убивает listener на ЛЮБОМ сообщении в группе

**Где:** `scripts/notary/meetings_listener.py:915-920` (`_chat_context_series`), цикл — `:3118-3121`.

**Доказательство (прогон).** `registry._read_yaml` на верхнем уровне не-словаря делает
`raise SystemExit(...)` (`cli/registry.py:109`). `SystemExit` — потомок `BaseException`, `except Exception`
его не ловит; проверено прогоном:

```
битый watched.yaml (верхний уровень — список):
   _chat_context_series: ПРОБРОСИЛ SystemExit('/var/.../r2-registry')
   maybe_route_to_send_artifact: ПРОБРОСИЛ SystemExit → цикл listener'а ловит только Exception
   except Exception НЕ ловит SystemExit (подтверждено прогоном)
```

**Что сломается.** `process_message` обёрнут в `except Exception` (`:3119`) — `SystemExit` пролетает
насквозь, из `while True`, из `main()` и гасит процесс. `save_offset(offset)` стоит ПОСЛЕ цикла по
апдейтам (`:3121`) — offset не сохранится, systemd поднимет listener, Telegram отдаст тот же апдейт,
процесс снова умрёт. Получаем цикл перезапусков, в котором мёртв весь бот (протоколы, статусы,
вечерний блок в чате), пока человек руками не починит YAML.

**Почему это новое.** До дифа этот путь реестр не читал вовсе: единственное чтение в listener'е было в
`maybe_route_to_set_chat_command` (`:1189`, там та же дыра, но за узким гейтом «владелец набрал команду
смены чата»). Диф расширяет триггер до «кто угодно написал что угодно в любой группе» — и делает это
ровно перед Фазой 7, где по плану владелец руками проходит реестр целиком и проставляет режим
каждой серии. Вероятность кривой правки в этот момент максимальная.

**Как чинить (2 символа).** В `_chat_context_series` ловить `BaseException` (или явно
`except (Exception, SystemExit)`) — модуль и так объявляет чтение реестра best-effort, а
`KeyboardInterrupt` в listener-потоке ловить не жалко:

```python
except BaseException as e:  # noqa: BLE001 — SystemExit из _read_yaml не должен валить listener
```

Тест-сторож: `_chat_context_series` при `load_watched`, кидающем `SystemExit`, возвращает `([], "SystemExit")`.

### Н2. Реестр читается ДО дешёвого гейта — 10 мс YAML на каждое сообщение в группе

**Где:** `scripts/notary/meetings_listener.py:1048-1057` — блок фолбэка стоит выше
`detect_artifact_request` (`:1058-1065`) и статус-гейта (`:1066-1072`).

**Доказательство (прогон).**

```
load_watched(): 10.74 мс за вызов (16 записей / 6 КБ)   ← копия боевого реестра
   он же на 100 записях: 40.29 мс
detect_artifact_request: 0.0027 мс                      ← гейт, который стоит ПОСЛЕ чтения
обычной болтовни: 6 сообщений → чтений реестра: 6
   в личке владельца: 6 сообщений → чтений реестра: 0
```

Из 10.1 мс на чтение файла уходит 0.024 мс — всё остальное чистый `yaml.safe_load` (pyyaml без
C-loader'а). То есть на каждое «привет» в группе однопоточный listener тратит в **3700 раз** больше,
чем стоил бы гейт, который это сообщение и так отбросит.

**Что сломается.** Функционально — ничего, это лишняя работа на горячем пути. Но: (а) она умножает
радиус Н1 с «сообщение похоже на просьбу» до «любое сообщение»; (б) если listener когда-нибудь
поедет на python без pyyaml (`send_artifact.py:17` прямо говорит «системный python3.9 без venv»),
фича молча превратится в no-op с исключением на каждое сообщение; (в) задаёт образец «читаем реестр
до гейта», который Ф2 (команда переключения) и Ф3 (чтение режима) скопируют.

**Конвенция проекта — обратная.** Соседний роут в этом же файле читает реестр только ПОСЛЕ узкого
парса команды (`:1122-1129` парсер → `:1189` `load_watched`). Кеша у соседей нет: конвенция —
инъекция готового `watched` параметром (`lib/series_markup.py:30` `_load_watched_safe(watched=None)`,
`lib/pending_reconciler.py:1393`), но и вызываются они раз на встречу, а не раз на сообщение.

**Как чинить.** Перенести блок `:1048-1057` ниже статус-гейта (перед `if not series:` на `:1073`).
Правка безопасна: ни `series`, ни `ambiguous_series` до `:1073` не читаются. **Проверено прогоном** —
после переноса:

```
test_iss51_mode_registry.py → 38 тестов OK
test_send_artifact.py       → 16 тестов OK
болтовня: 5 сообщений → чтений реестра 0 (было 5)
настоящая просьба: чтений реестра 1, роут отработал штатно
```

### Н6. `test_owner_dm_returns_nothing` не проверяет ничего — мутант выжил, и тест лезет в реальный реестр

**Где:** `tests/test_iss51_mode_registry.py:362-366`.

**Доказательство.** Мутант M10 (ранний выход `if cid is None or cid == allowed_chat` удалён из

покраснеет по причине, к коду отношения не имеющей.

**Как чинить:** `with mock.patch("notary.cli.registry.load_watched") as lw:` вокруг вызова +
`lw.assert_not_called()`. Тогда тест проверяет ровно утверждение «в личке реестр не трогаем».

  `if raw is None or (isinstance(raw, str) and not raw.strip()): continue`.
- **Н13. `if cid is None` в `_chat_context_series:913`** недостижим: единственный вызыватель уже
  вышел по `if cid is None: return False` (`:1036`). Безвредно, но это одна из «трёх ветвей», которые

## Пункт 2 отдельно: дубли

Перебор записей `watched` в новом коде — **четвёртая и пятая копии** одного цикла
(`get_telegram_chat_id_for_series:402`, `find_series_bindings:424`, `get_company_for_series:585`,
`get_visibility_for_series:603`, `get_genre_for_series:622`). Предикат совпадения серии
`ws == series or normalize_series_key(ws) == norm` — **третья копия**
(`get_telegram_chat_id_for_series:407-409`, `set_telegram_chat_id_for_series:651`,
`series_open_questions_mode:506-507`).

**Вердикт: в порядке, не чинить.** Конвенция берётся из репозитория: файл уже держит пять таких
циклов сознательно (каждый резолвер самодостаточен и stdlib-only), извлечение общего хелпера сейчас
