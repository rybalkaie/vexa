## СЛЕД 1 — прошёл путь как пользователь

Команда: `PYTHONDONTWRITEBYTECODE=1 python3 trace1.py`
Реестр стенда: 3 серии — `series-ezhenedelnaya-koordinaciya-8399ea` (чат `-1001207402590`),
`anzhee-direktorat` (чат `-5428752538`), `anzhee-vystavka-st1` (чата нет).

### (а) Владелец в чате серии: «эта серия — шпаргалка»

```
СЦЕНАРИЙ: а) в групповом чате Координации
  набрал : 'эта серия — шпаргалка'

      Серия «Еженедельная координация» и так в режиме шпаргалки — ничего не менял.
  в реестре теперь:
      series=series-ezhenedelnaya-koordinaciya-8399ea      open_questions_mode=None

- **что увидел владелец:** «и так в режиме шпаргалки — ничего не менял»;

🟡 Дефолт — `last-only`, поэтому **самая первая команда «эта серия — шпаргалка» всегда
немой no-op**: явный выбор владельца в файл не попадает. В боевом реестре поле не
проставлено ни у одной из 16 серий (см. след 4) — значит это состояние по умолчанию для
всех. Поведение при этом верное, но «выбрано шпаргалкой» и «никто не выбирал» в реестре
неразличимы; если дефолт когда-нибудь поменяют, все такие серии молча перевернутся.

### Переход 1: текст сообщения → `parse_mode_command`

| вход | результат |
|---|---|
| `''`, `'   '`, `'\n\n\t  \n'`, `None` | `None` (не наша команда) ✅ |
| `12345` (не строка) | `AttributeError: 'int' object has no attribute 'strip'` ⚪ из роута недостижимо: `(msg.get("text") or "").strip()` всегда даёт str |
| `'эта серия\n\n— шпаргалка'` | `ModeCommand(set, last-only, '')` — переводы строк не мешают ✅ |
| `'эта серия — шпаргалка\nи ещё пара слов'` | `None` — слово режима не последнее ✅ |
| 80 021 символ | `ModeCommand(set, last-only, series_ref=<80 000 симв.>)`, разбор 177 мс 🟡 |
| `'серию ((([[[.*+?  — шпаргалка'` | `series_ref='((([[[ *+'` — regex-метасимволы не компилируются, падения нет ✅ |

владелец не увидит **ничего**. Это ровно тот молчаливый провал, от которого фазу защищали
правилом R-REPLY. Проверено и на 5 000-символьном имени: ответ уходит целиком.

## СЛЕД 3 — где ещё живёт этот же класс

### (а) Другие команды бота, меняющие настройки серии

```
$ grep -rn '^def set_\|^def add_\|^def remove_' cli/registry.py
cli/registry.py:672:def set_telegram_chat_id_for_series(...)
cli/registry.py:698:def set_open_questions_mode_for_series(...)
```
Команд-настроек серии в боте ровно **две**: смена чата (`maybe_route_to_set_chat_command`)
и новый режим. Owner-гейт устроен ОДИНАКОВО и слово в слово:

| | смена чата (стр. 1207–1215) | режим (стр. 1501–1515) |
|---|---|---|
| признак владельца | `is_dm = cid == allowed_chat`; `from_id != allowed_chat` → отказ | то же |
| реакция не-владельцу | `False` + `logger.info`, без сообщения | то же |
| что под гейтом | вся команда | `set` + любой запрос по ЯВНОМУ имени серии |
| что вне гейта | — | вопрос о режиме СВОЕГО чата |
| список известных серий | печатается всем, кто дошёл до «не нашёл» | печатается только владельцу (`list_known=is_owner`) |

Новый роут **строже** соседа в двух местах (запрос чужой серии по имени и список серий за
гейтом). Расхождение осознанное и в плюс.

**Все места, где бот пишет в чат, отличный от того, откуда пришло сообщение** (скан всех
вызовов `send_message` в `meetings_listener.py` с разбором первого аргумента-чата):

```
  строка 1631  чат-получатель: series_chat   ← НОВЫЙ роут, ⚙️-уведомление в чат серии
  строка 2881  чат-получатель: int(chat_id)  ← перевыпуск, chat_id = тот же исходный чат
```
То есть **фаза 2 вводит в слушатель первую и единственную «рассылку»**: сообщение одного
человека заставляет бота написать в комнату других людей. Защита проверена поведением:

```
  посторонний из своей лички    роут=False сообщений=0, в чужой чат: нет
  посторонний из группы серии   роут=False сообщений=0, в чужой чат: нет
  ВЛАДЕЛЕЦ из своей лички       роут=True  сообщений=2, в чужой чат: [-5428752538]
```
Адрес берётся из реестра (`get_telegram_chat_id_for_series`), а не из текста — подменить
его сообщением нельзя. Единственный способ «выстрелить» — сам владелец: см. 🔴 из следа 1
(ложное срабатывание) и 🟡 из пятого вопроса (уведомление в группу выключенной серии).
Все остальные отправки в чат серии (`runner.py:411`, `lib/llm_postprocess.py:4187`) — это
доставка протоколов по расписанию, инициативы одного человека там нет.

### (б) Запись значения сразу в НЕСКОЛЬКО записей серии

Соседей ровно один — `set_telegram_chat_id_for_series`. Сравнил поведением
(`trace3.py`, оба сеттера на одном и том же реестре):

```
  ключ «»                 режим: обновил 0   чат: обновил 2   ⚠️ РАСХОДЯТСЯ
  ключ из пробелов        режим: обновил 0   чат: обновил 2   ⚠️ РАСХОДЯТСЯ
  пустая строка           режим: обновил 0   чат: обновил 0
  нормальный ключ         режим: обновил 1   чат: обновил 1
  ключ другого регистра   режим: обновил 1   чат: обновил 1

  --- мусорная (не-словарь) запись в реестре:
  режим:  1
  чат  : ⚠️ AttributeError: 'str' object has no attribute 'get'
  резолв: ⚠️ AttributeError: 'str' object has no attribute 'get'
```
Совпадает в главном (матч точный ИЛИ нормализованный, «все записи серии»), **расходится в
двух местах — и оба в пользу нового кода**: новый сеттер не матчит по пустоте и переживает

```

  тот же реестр, порядок ОБРАТНЫЙ    → читатель говорит: last-only
```
Read-after-write действительно зависел бы от порядка строк в файле. Решение верное.
