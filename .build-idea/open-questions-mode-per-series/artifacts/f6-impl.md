## Пункт 1 плана. ИИ-первый разбор по образцу `ack_understand`

Разбор стал трёхъярусным — ровно та же схема, что вылечила ответы на вопросы бота (ISS-49):
**ИИ решает, ПРОСЬБА ли это; детерминированный код решает, ЧТО можно отдать и можно ли вообще.**

```
текст сообщения
   │
   ├─1─ БЫСТРЫЙ ПУТЬ: узкая регулярка ISS-45 (глагол + объект)  ──► ответ, модель не зовём
   │        «пришли протокол», «скинь открытые вопросы»
   │
   ├─2─ ИИ-ЯРУС (флаг ENABLE_SEND_ARTIFACT_AI, дефолт-OFF)
   │        пред-фильтр should_ask_ai(): объект вообще упомянут? длина ≤ 600?
   │        understand_request() → {"intent": "send|none", "artifact": "protocol|digest|unknown"}
   │        модель — mixed_reply_split._SPLIT_MODEL, вызов — claude_cli.call_claude_print
   │
   └─3─ ВЕРИФИКАЦИЯ КОДОМ: _verify_artifact() — какой артефакт, решают СЛОВА
            названы вопросы/задачи → digest;  протокол/итоги встречи → protocol
            названы оба → подсказка модели → контекст ответа → протокол
            назван только «файл/версия/документ» → нужен контекст ответа, иначе None
```

Заимствованное у `ack_understand` один-в-один: форма флага (`raw in ("1","true","yes","on")`),
инъекция `answer_fn` вместо реального Claude для тестов, `parse_*_json` со срезанием ```-обёртки
и `raw_decode`, гашение ЛЮБОГО исключения ИИ в `None` (сбой модели не валит листенер), опасная
тройка (сообщение — ДАННЫЕ в anti-injection рамке; текст не логируем; сырой ответ не персистим).

Отличие от `ack_understand` сознательное: там ИИ отдаёт номера задач, и код проверяет их
диапазон; здесь у ИИ вообще нет права назначить артефакт — его ответ по артефакту это лишь
**подсказка на случай ничьей**. Если модель скажет «protocol», а в тексте «открытые вопросы» —
уйдёт дайджест (тест `test_words_beat_the_model`). Причина: ошибка модели здесь стоит дорого —
это вываленный в рабочий групповой чат чужой документ.

### 🔴 Находка разведки Н7 закрыта

Разведка права: гейт в артефакт-роуте не проверялся ни одним тестом. Существующий
`test_status_reply_not_stolen` подаёт «закрой третью» — текст БЕЗ глагола отправки, он отсекается
детектом и до гейта не доходит; удалить гейт — тест останется зелёным.

Новый класс `TestNoHijack` подобран так, что **детект на этих текстах СРАБАТЫВАЕТ**:

| текст | статус-маркер | детект (был бы) | роут |
|---|---|---|---|
| «пришли протокол — по второй задаче всё сделано» | `done` | `protocol` | `False` |
| «скинь открытые вопросы, задачу по складу я сделал» | `done` | `digest` | `False` |
| «вышли актуальный файл с открытыми вопросами, кстати первый вопрос уже закрыт» | `done` | `digest` (ИИ-ярус) | `False` |
| «вместо Иванов правильно Иванова, и вместо Zil правильно Zeal — пришли протокол» | edit-heavy | `protocol` | `False` |
| «вышли протокол, там вместо Иванов правильно Иванова, и вместо Zil правильно Zeal» | edit-heavy | `protocol` (ИИ-ярус) | `False` |

Отдельный тест `test_fixtures_are_really_intercept_candidates` **проверяет сами фикстуры**:
`detect_status_intent` на них не None, `looks_edit_heavy` True, а `detect_artifact_request` —
не None. Без него класс был бы зелёным вхолостую (доказывал бы «детект не сработал», а не «гейт
держит»). Каждый тест дополнительно требует `understand_request.assert_not_called()` — то есть
на статус и правку модель не зовётся ни разу.

Гейт покрыт на обоих путях резолва серии: по привязке чата (`_chat_context_series`) и по реплаю

## Пункт 4 плана. Какие фразы понимаются, а какие сознательно нет

**Понимаются (флаг ON):**

| фраза | что уходит | ярус |
|---|---|---|
| **«Вышли актуальный файл с открытыми вопросами»** (дословная фраза владельца) | дайджест | ИИ |
| «скинь протокол» | протокол | регулярка |
| «дай посмотреть вопросы» | дайджест | ИИ |
| «выслать протокол по вчерашней встрече» | протокол | ИИ |
| «шли протокол» | протокол | ИИ |
| «вышлите пожалуйста открытые вопросы» | дайджест | ИИ |
| «не могу найти, отправьте ещё раз итоги встречи» | протокол | ИИ |
| «продублируй список задач по встрече» | дайджест | ИИ |
| «вышли файл» в ОТВЕТЕ на дайджест/протокол | по тому, на что ответили | ИИ |

**Сознательно НЕ понимаются (и это правильный ответ, а не пробел):**

| фраза | почему |
|---|---|
| «вышли файл» / «перекиньте документ» / «вышлите актуальную версию» **без реплая** | инвариант Ф1 (ISS-52): объект назван неоднозначно, разрешать нечем; в группе это переписка людей, а бот вывалил бы туда протокол встречи. Держится КОДОМ, а не доверием к модели: даже если ИИ уверенно скажет «send/protocol» — `None` |
| «вышлите файл с ценами», «дайте актуальную версию договора» | то же: чужой документ |
| «вышли итоги месяца по продажам» | «итоги/резюме/сводка» считаются протоколом только рядом со словом про встречу — иначе «резюме кандидата» и «итоги месяца» тянули бы протокол |
| «пришли протокол — по второй задаче всё сделано» | статус-ответ, уступаем статус-роуту (см. пункт 2) |
| «вместо X правильно Y, вместо A правильно B, пришли протокол» | пачка правок, уступаем роуту правок |
| «привет», «спасибо», «завтра встречаемся в 11» | объект не назван — до модели даже не доходит |

## Что решил сам

1. **ИИ не может назначить артефакт, только подсказать при ничьей.** План говорит «модель
   определяет намерение и какой именно артефакт, код верифицирует». Верификацию сделал жёсткой:
   когда слова сообщения решают однозначно — они и решают, даже против модели. Цена ошибки
   несимметрична: не тот документ в рабочем чате хуже, чем переспрос.
2. **Пред-фильтр `should_ask_ai` перед вызовом модели.** Без него каждое «привет» в каждой группе
   стоило бы вызова `claude` — деньги, квота и СЕКУНДЫ В ЦИКЛЕ листенера. Фильтр требует, чтобы
   объект-документ был вообще упомянут (то же требование Ф1 к свободной формулировке) и текст был
   короче 600 символов. Фильтр может только сэкономить вызов, ложной отправки вызвать не может.
3. **Потолок таймаута 30с** (`SEND_ARTIFACT_AI_TIMEOUT`, иначе `min(_split_timeout(), 30)`). Общий
   таймаут сплиттера — 120с, а этот вызов сидит в цикле обработки сообщений: одна болтливая фраза
   заморозила бы бота на две минуты. Деградация честная (фолбэк — регулярка), поэтому режем жёстко.
4. **Гейт «не крадём» поднят ВЫШЕ разбора и дополнен `looks_edit_heavy`.** Обоснование в пункте 2.
   Формально план просил «сохранить»; сохранение на прежнем месте оставляло бы модель звонить на
   статус-ответы — платно и без нужды.
5. **На ИИ-пути голый «файл» НЕ разрешается через `allow_bare_file`, только через `reply_surface`.**
   Регулярный путь тут мягче (без реплая с `allow_bare_file=True` отдаёт протокол) — его не трогал,
   он закрыт тестами ISS-45. Новый путь строже сознательно: свободная формулировка, не назвавшая
   артефакт, кодом не верифицируема в принципе.
6. **Тест на фикстуры (`test_fixtures_are_really_intercept_candidates`).** Тест, который проверяет,
   что остальные тесты не зелёные вхолостую. Ровно эта дыра и была в Н7.

## Долги (в follow-ups, не в этой фазе)

- Пер-чат rate-limit на вызовы ИИ-яруса: сейчас частота ограничена только пред-фильтром. В очень
  болтливом чате с частым словом «вопрос» это заметный поток вызовов haiku.
- Разбор синхронный. Если на проде заметим паузы в реакции бота — выносить в фоновую очередь
  (как `reply_understand_queue`).
