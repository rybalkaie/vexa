## Находки

### 🔴-1. Слова «вопрос / задача / пункт» обходят инвариант `allow_bare_file`

`scripts/notary/lib/send_artifact.py:127-131, 339-360`

`_WIDE_DIGEST` включает голые основы `вопрос\w*` и `задач\w*`. В `_verify_artifact`
это попадает в ветку «класс назван ОДНОЗНАЧНО»:

```python
prot, dig, amb = _object_classes(t)
if dig and not prot:
    return "digest"          # ← ни allow_bare_file, ни reply_surface не смотрим
...
if amb and allow_bare_file and reply_surface in ("protocol", "digest"):
```

Защита ISS-52 (`allow_bare_file`) стоит **только на ветке `amb`** — «файл / версия /
документ». Стоит модели сказать «send», и любая фраза со словом «вопрос» отдаёт
дайджест **без реплая, без глагола отправки, без контекста**. Прогон, `allow_bare_file=False`:

```
   молчит  —        «вышлите файл с ценами»            ← ветка amb, прикрыта
   молчит  —        «вышлите документ по договору»     ← ветка amb, прикрыта
🔴 ОТДАЁТ  digest   «какие вопросы по бюджету?»
🔴 ОТДАЁТ  digest   «вопросы по оплате в бухгалтерию»
🔴 ОТДАЁТ  digest   «задача не поставлена»
🔴 ОТДАЁТ  digest   «у нас вопрос»
🔴 ОТДАЁТ  digest   «вопросы?»
```

Почему это не поймали: `test_bare_object_still_needs_context` проверяет ровно четыре
фразы, и все — из ветки `amb` («вышли файл», «вышлите актуальную версию»,
«перекиньте документ», «вышлите файл с ценами»). Класс «вопрос/задача» не проверен
ни одним тестом, поэтому дыра зелёная, а комментарии в коде и шапка теста заявляют
«инвариант Ф1 сохранён» шире, чем он держится.

Отсюда же — все 6 новых ложных срабатываний на бытовой выборке.

Что предлагаю: либо требовать для дайджест-ветки составную форму (как в
`_OBJ_DIGEST` быстрого пути: «открытые вопросы», «список вопросов», «дайджест»,
«висяки»), либо распространить условие `allow_bare_file`/`reply_surface` на голые
`вопрос\w*`/`задач\w*` наравне с `_WIDE_FILE`. Плюс тест на этот класс.

### 🔴-2. Одиночная правка протокола не защищена гейтом

`scripts/notary/meetings_listener.py:1110-1116`, порог в `pending_status_reply._EDIT_HEAVY_MIN_MARKERS` (2)

Гейт отсекает **пачку** правок (≥2 маркера). Одиночная правка порога не набирает и
до модели доходит; дальше решает только она. Прогон (reply на протокол, «щедрая» модель):

```
   уступил  —          edit_heavy=True   «вместо Иванов правильно Иванова»
🔴 УКРАЛ   protocol    edit_heavy=False  «поправь фамилию в протоколе»
🔴 УКРАЛ   protocol    edit_heavy=False  «исправь, пожалуйста, дату встречи в протоколе»
🔴 УКРАЛ   protocol    edit_heavy=False  «в протоколе опечатка в названии компании»
🔴 УКРАЛ   protocol    edit_heavy=False  «протокол верный, только замени Zil на Zeal»
🔴 УКРАЛ   digest      edit_heavy=False  «в списке вопросов третий пункт сформулирован неверно»
🔴 УКРАЛ   protocol    edit_heavy=False  «по итогам встречи там не так записано, посмотри протокол»
   уступил  —          edit_heavy=True   «вместо Zil правильно Zeal, и вместо 5 правильно 6»
```

**6 из 8 украдено** при ошибке модели, **0 из 8** при модели, следующей промпту.
Ущерб конкретный: вместо шлюза правок человек получает переприсланный протокол,
а сама правка теряется — тот же класс, что инцидент 20.07, ради которого
`looks_edit_heavy` и заводили.

Это новая поверхность: до фазы 6 «поправь фамилию в протоколе» не имело глагола
отправки, регулярка молчала, и роут уступал детерминированно.

Порог 2 сам по себе трогать не надо (он защищает «задачу заменили, закрыто»), но
для артефакт-роута условие уместнее строже, чем для статус-роута.

### 🟡-1. Позиция роута ничем не закреплена

Три мутанта выжили: роут удалён из `process_message` (M3), перенесён после
digest-роута (M15), перенесён перед ack-роутом (M16) — ни один тест не покраснел.
Сама позиция сейчас **правильная** (проверено по коду: `3548` ack → `3554`
send_artifact → `3562` digest), но именно её докстринг называет частью защиты от
перехвата, а регрессию в ней никто не поймает.

### 🟡-2. Потолок таймаута 30с пробивается `CLAUDE_MIN_TIMEOUT`

`_ai_timeout()` честно режет до 30 (проверено: сплиттер 120 → 30, явные 600 → 30,
мусор → 30). Но `call_claude_print` поверх применяет глобальный пол
`CLAUDE_MIN_TIMEOUT` (`claude_cli.py:73-78`). Прогон с
`SEND_ARTIFACT_AI_TIMEOUT=10` + `CLAUDE_MIN_TIMEOUT=900` → в subprocess ушёл
**timeout=900**. Вызов сидит в цикле листенера синхронно: одна фраза может
заморозить бота на 15 минут. В `.env.notary.example` переменной нет (по умолчанию 0),
но заведена она ровно под длинные встречи — то есть на проде может оказаться.

### 🟡-3. Пред-фильтр пропускает в модель почти весь рабочий трафик

`should_ask_ai` пропускает **19 из 20** бытовых фраз: слова «вопрос», «задача»,
«файл», «документ», «версия» — самые частые в рабочих чатах. После гейтов роута
реально доходит до модели **14 из 20** (без реплая) и **10 из 20** (реплай).

Два следствия. Приватность: в `claude` уезжает **чужой контент** — тексты коллег, не
владельца, по десятку сообщений на два десятка. Производительность: столько же
синхронных subprocess-вызовов в цикле обработки сообщений.

Докстринг обещает «звать модель на каждое привет незачем» — «привет» действительно
отсекается, но экономии это почти не даёт.

### 🟡-4. Инвариант «текста в логах нет» не закреплён тестом

Сейчас текст **не течёт** — проверено на пяти исходах (понял моделью, недоступна,
отказала, парс упал, код отказал): ни «Ромашка», ни «4 млн», ни фрагмента фразы в

«опасной тройке» пройдёт мимо тестов.

### 🟡-5. Статус-гейт молча съедает легитимную просьбу, не оставляя строки в логе

Фраза «вышли актуальный файл с открытыми вопросами, первый вопрос уже закрыт» —
одновременно просьба и статус. Гейт отдаёт её роутам ниже: `claimed=False` и **ни
одной строки в журнале**. Без реплая ниже её не подхватит ни digest-, ни
status-роут → человек получает тишину, а по логам понять, почему бот промолчал,
невозможно. Это ровно тот сценарий, ради которого фазу делали.
