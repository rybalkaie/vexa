# Список несущих утверждений

**Источник — раздел «Критерий "фича готова"» плана.** Реестра `*-requirements.md` рядом с планом нет,
поэтому этот раздел и есть список (§2 ворот сдачи). Формулировки НЕ переписываются и НЕ сокращаются —
только закрываются. Он же задаёт места для мутаций (§4) и становится листом решений (§5).

| № | Утверждение (дословно из плана) | Фаза | Состояние |
|---|---|---|---|
| Т1 | В серии-шпаргалке к встрече приходит список задач **только прошедшей встречи**; ни один вопрос старше её в списке не появляется — даже в первый раз после переключения. | Ф3 | открыт |
| Т2 | Шпаргалка не просит статусов: нет нумерации под ответ, нет инструкции «ответьте статусом», подпись справочная. | Ф3 | открыт |
| Т3 | В протоколе серии-шпаргалки нет раздела «Вопросы с прошлых встреч…», и следующая выжимка не наследует чужой хвост. | Ф3 | открыт |
| Т4 | В серии-накоплении (`anzhee-direktorat`) поведение не изменилось ни в одном месте — тот же дайджест, те же статусы, тот же раздел в протоколе. | Ф1–Ф3 | открыт |
| Т5 | Владелец переключает режим любой серии в обе стороны командой боту и получает видимое подтверждение; на вопрос «в каком режиме серия» бот отвечает. | Ф2 | открыт |
| Т6 | После переключения в накопление счёт висяков начинается с нуля — старое не всплывает (решение 7). | Ф2–Ф3 | открыт |
| Т7 | Отклонённая встреча («нет, не писать») больше не предлагается в вечернем блоке. | Ф4 | открыт |
| Т8 | Время встречи в вопросе бота и в его подтверждении совпадает. | Ф4 | открыт |
| Т9 | На одну встречу заводится один бот, даже если событие видно в двух календарях. | Ф5 | открыт |
| Т10 | В групповом чате серии просьба прислать файл срабатывает без ответа-реплая на протокол; формулировка глагола роли не играет. | Ф1 + Ф6 | открыт |

## Места для мутаций (фиксируются здесь, не выбираются в конце)

| № | Что ломаем | Ожидаемый сторож |
|---|---|---|
| М1 (Т1) | фильтр происхождения задач в `last-only` → вернуть весь `open_tasks` | тест «сразу после переключения показываются только задачи последней встречи» |
| М2 (Т3) | снять гейт хвоста в `clarify_worker` (второй call-site) | тест на поздний clarify-путь |
| М3 (Т4) | сделать `last-only` дефолтом для серии-накопления | тест «`carry` не изменился ни на байт» |
| М4 (Т7) | не сохранять реестр при `rejected > 0` | тест «повторный вечерний блок не предлагает отклонённое» |
| М5 (Т9) | убрать сверку `iCalUID` при записи в реестр | тест «два календаря — одна запись» |
| М6 (Т10) | снять гейт `detect_status_intent` перед ИИ-разбором | тест «статус-ответ НЕ перехватывается» |
